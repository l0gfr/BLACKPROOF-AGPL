# BLACKPROOF Methodology

Version: blackproof-method-v0.1.0-alpha

BLACKPROOF is built around one core idea: a cyber answer is only useful if it can be defended with evidence.

The method is:

1. Source
2. Requirement
3. Evidence
4. Test
5. Debt
6. Action

BLACKPROOF does not sell conformity. It sells a structured cyber evidence dossier.

## Source

A source is the origin of the demand: supplier questionnaire, client audit, contractual clause, NIS2/ReCyF expectation, internal risk review or board request.

## Requirement

A requirement is the security expectation derived from the source.

## Evidence

Evidence is the material used to support the answer: policy, procedure, ticket, report, log, register, screenshot, attestation or controlled extract.

## Test

A test evaluates whether the evidence is fresh, relevant, scoped and reusable.

## Debt

ProofDebt is the gap between what is declared and what is supported by evidence.

## Action

An action is a concrete remediation step: add evidence, produce a controlled extract, document a reservation, exclude scope or create a remediation task.

## Non-promise

BLACKPROOF is not a certification authority, not a legal advisor and not a qualified audit provider.
